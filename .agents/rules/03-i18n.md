# Internationalization (next-intl) Rules

- Route all user-facing strings through `next-intl`—including visible text, form labels, placeholders, `aria-label` attributes, empty/error states, and `sileo` toast titles/descriptions. Never hardcode copy in components, hooks, actions, or services.
- Keep `src/messages/en.json`, `src/messages/es.json`, and `src/messages/fr.json` structurally identical across all three locales (`LOCALES` in `src/i18n/routing.ts`, display metadata in `src/config/locale.ts`).
- Organize translation keys under `features.<feature>.<area>` for feature modules (e.g. `features.blog.composer`, `features.blog.categories`), `components.<area>` for shared layout/UI, and `common.*` for reusable actions and fallback errors.
- Structure domain error toast translations as `features.<feature>.<scope>.errors.<REASON>.{title,description}` with matching ICU placeholders (`{slug}`, `{name}`, `{title}`) consumed by `useDomainErrorToast` or `translateErrorReason` (`src/hooks/use-domain-error-toast.ts`).
- Use `getTranslations({ locale, namespace })` and `getFormatter({ locale })` from `next-intl/server` in Server Components and `generateMetadata` (awaited in parallel with `Promise.all`), and `useTranslations(namespace)` from `next-intl` in Client Components.
- Import locale-aware navigation primitives (`Link`, `useRouter`, `usePathname`, `redirect`) from `@/i18n/navigation` (`src/i18n/navigation.ts`) in UI components instead of `next/navigation` (server-side `notFound()` or `redirect(\`/\${locale}/...\`)` from `next/navigation` is acceptable in Server Components).
- Revalidate both unprefixed and all localized (`/${locale}...`) routes after server mutations using `revalidateLocalizedPaths` (`src/lib/actions/revalidate-localized-paths.ts`).
- Run `bun run i18n:check` (`src/scripts/check-locales.ts`) whenever any file in `src/messages/` is modified and fix any key parity mismatches before completing the task.
